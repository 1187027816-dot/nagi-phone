# Netlify 自助部署 README 设计

## 目标

在项目根目录新增一份中文 `README.md`，让不熟悉网站部署的用户可以自行把弯弯部署到 Netlify。文档以连接 GitHub 的自动部署方式为主，并提供 Netlify Drop 手动上传作为备用方案。

## 受众与写作原则

- 主要面向第一次使用 GitHub 或 Netlify 的普通用户。
- 使用 Netlify 当前界面中的名称，并提供必要的官方页面链接。
- 每一步说明用户需要点击什么、填写什么，以及成功后会看到什么。
- 只介绍完成部署所需的设置，避免引入命令行、构建工具和无关的高级选项。

## README 结构

1. 项目简介和部署说明
2. 部署前准备
3. 推荐方案：连接 GitHub 自动部署
4. 备用方案：通过 Netlify Drop 手动上传
5. 部署后的常用操作
6. 手机添加到主屏幕
7. 数据与隐私提醒
8. 常见问题排查

## GitHub 自动部署流程

文档将引导用户：

1. Fork 本仓库到自己的 GitHub 账户。
2. 注册或登录 Netlify。
3. 选择 `Add new project` 和 `Import an existing project`。
4. 授权 GitHub，并选择刚刚 Fork 的仓库。
5. 确认生产分支为仓库默认分支。
6. 将构建命令留空，将发布目录设为 `.`。
7. 发布项目并访问生成的 `netlify.app` 地址。
8. 说明以后推送到生产分支时会自动部署。

## 手动上传流程

文档将引导用户下载仓库 ZIP 并解压，确认上传文件夹根目录直接包含 `index.html`，然后前往 Netlify Drop 上传整个项目文件夹。更新项目时，需要将更新后的文件夹重新上传到同一个 Netlify 项目。

## 部署后说明

- 可在 Netlify 中修改默认项目名称和添加自定义域名。
- 项目不需要 Netlify 环境变量；用户使用的模型接口和 API Key 在应用设置页中配置。
- 应用数据主要保存在当前浏览器本地。更换浏览器、设备、域名或清理网站数据时，原数据不会自动迁移，因此应先导出备份。
- 页面依赖部分外部 CDN 和图片资源，使用时需要网络连接。

## 排错范围

README 将覆盖以下高频问题：

- 部署后显示 404：检查 `index.html` 是否位于发布目录根部，发布目录是否为 `.`。
- 页面没有样式或功能不完整：检查是否上传了完整的 `css`、`js`、`img` 和 `audio` 目录。
- GitHub 更新后网站没有变化：检查生产分支、部署记录，并尝试清除浏览器缓存或重新打开页面。
- 换域名后找不到数据：说明浏览器会按站点来源隔离本地数据，换域名前先导出备份。

## 验收标准

- 根目录存在 `README.md`。
- GitHub 连接部署排在手动上传之前。
- 两种方式都能由普通用户独立完成。
- 配置与当前项目一致：无构建命令、发布目录为 `.`、无需环境变量。
- README 明确说明自动更新方式、本地数据边界和常见故障处理。
- 文档中的 Netlify 操作名称与官方文档一致。
